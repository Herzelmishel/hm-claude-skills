# Soft-Circle Rules — preseed-pipeline

The soft-circle map is the FOMO engine of the round. Once an investor is at `soft_commit` AND has granted `soft_circle_permission = yes`, they can be referenced (descriptor first, name only after explicit user confirmation) to other prospects to compress the round.

All status / commitment values reference `~/fundraising/.sys/vocabulary.yaml`.

---

## When to add an investor to the soft circle

An investor enters the soft-circle map when ALL of the following are true:

1. `commitment_status` is in {`soft_commit`, `hard_commit`, `terms_sent`, `signed`, `wired`} (per vocabulary.yaml)
2. `soft_circle_permission = yes` in `commitments.csv`
3. The user has explicitly confirmed within the last 14 days that the soft-commit is real (not a "polite yes")

If `soft_circle_permission = ask`, the user must request explicit permission from the investor before name-dropping or descriptor-dropping. The default is `no` until the conversation has happened.

If `soft_circle_permission = no`, the investor is NEVER referenced in any external pitch, regardless of how strong the social proof would be.

---

## Descriptor-first sequencing strategy

Always lead with a descriptor before a name. Most investors will be persuaded by the descriptor; the name is held in reserve for the moment when it tips conviction.

### Default descriptor pattern

> "We have [role/sector] investors in the soft circle"

Examples:
- "We have a B2B-SaaS operator-angel and a commerce-vertical micro-VC in the soft circle"
- "Soft circle includes a Shopify-app-acquired founder and an AI-infra GP from a tier-1 fund"
- "Our soft circle includes operators from [sector] and one pre-seed-leading micro-VC"

### When to drop the actual name

Only after explicit user confirmation in the same session, AND only when ONE of:

1. The new prospect explicitly asks "who else is in?"
2. The user has decided this prospect specifically values social proof from this named investor (e.g., they've cited them on a podcast)
3. The named investor has given second-tier permission ("you can name me to other angels but not to funds") and the prospect fits

The user — not the skill — makes the call to name. The skill prompts the user with the descriptor first and the candidate name(s) the user could choose to drop. The user types the name into the message draft. The skill never auto-drops the name.

---

## FOMO mechanics: which type of investor names appeal to which type of prospect

Different prospect archetypes are moved by different social proof. Match the soft-circle reveal to the prospect:

| Prospect type | Names that move them | Names that don't |
|---|---|---|
| Operator-angel (commerce founder) | Other commerce-founder-angels | AI-infra GPs |
| AI/SaaS angel | Pattern-matched AI angels and AI-infra GPs | Commerce operators |
| Micro-VC | Pre-seed funds with reputation, well-known operator-angels | Random angels |
| Pre-seed fund | Other named pre-seed funds, well-respected solo GPs | Most angels |
| Strategic angel (industry exec) | Industry peers, customer-archetype operators | VC names |
| Customer-advisor candidate | Customers in their adjacent space | Pure financial investors |

The user's job: match the strongest name in the soft circle to the prospect's archetype. The skill's job: surface the right names with the right descriptors.

---

## Confidentiality rules

- Never name-drop without `soft_circle_permission = yes`
- Never publish the soft-circle list outside Agentis (no decks, no investor updates, no LinkedIn)
- The `soft-circle-map.md` file is **internal** — it is the user's reference, not an investor-facing artifact
- If a referenced investor asks "where did my name come from?", the user must be able to point to a recorded permission grant — which lives in `commitments.csv` as `soft_circle_permission = yes`
- If permission is later withdrawn, set `soft_circle_permission = no` immediately; regenerate `soft-circle-map.md`; do not name-drop in any future communication

---

## Sequencing strategy: who to reveal to whom, in what order

### Stage A — early wave (0–2 commits)
- Use descriptors only
- Do not name-drop unless asked directly
- Purpose: establish that there's traction, not who specifically

### Stage B — mid wave (3–5 commits)
- Use the strongest archetype-match name when a prospect explicitly asks
- Save the strongest name for the highest-conviction prospect
- Purpose: tip prospects who are 80% convinced

### Stage C — closing wave (6+ commits, or first close visible)
- Reveal multiple names in sequence
- Lead with the highest-credibility match for each prospect
- Purpose: compress the round; trigger fence-sitter decisions

The soft-circle-map.md generated by `campaign_summary.py` shows three columns:
- Descriptor (always shown)
- Name (only shown to user, never auto-inserted into outreach drafts)
- Best-match prospect archetype

---

## What goes in `soft-circle-map.md`

```markdown
# Soft Circle Map — Wave [N]

## Active soft circle (permission = yes)

| Descriptor | Name (internal only) | Commit | Best-match prospect |
|---|---|---|---|
| Commerce-vertical operator-angel | [name] | $50K | Other commerce operators, micro-VCs |
| AI-infra solo GP | [name] | $250K | AI/SaaS angels, larger funds |
| Pre-seed fund partner | [name] | $750K (lead) | Other funds, strategic angels |

## Pending permission (permission = ask)

| Descriptor | Notes |
|---|---|
| Shopify-app-acquired founder | Asked at meeting on [date]; awaiting confirmation |

## No-go (permission = no)

| Descriptor | Notes |
|---|---|
| Stealth-mode angel | Explicit request not to name-drop. Respect. |

## Sequencing recommendations

1. For [next prospect]: lead with descriptor "[role/sector]"; if asked, drop name [name]
2. ...
```

`campaign_summary.py` regenerates this map after every soft-commit status change. The user reads this file before drafting any new outreach to a fence-sitter prospect.

---

## Common failure modes

| Failure | Why | Fix |
|---|---|---|
| Name-dropping before permission | Founder enthusiasm | Hard-fail in `validate_outreach.py` if a name appears in `outreach.csv` and `soft_circle_permission != yes` for that investor |
| Wrong archetype reveal | Wrong match between prospect and name | Use the FOMO mechanics table; ask user to confirm match before insertion |
| Treating "polite yes" as soft commit | Founder hears what they want | Require explicit confirmation in the last 14 days; if expired, prompt user before regenerating soft-circle-map.md |
| Soft circle revealed publicly | LinkedIn post, deck, investor update | Never put soft-circle list in any public artifact. Internal only. |
